这是一个用来记录代码、生活与思考的地方。它没有评论区、没有账号系统，也不打算
在浏览器里做任何需要后端才能完成的事。所有页面在构建时生成，写文章就是把
Markdown 文件放进仓库。

## 这个站点是什么

UIVIU 是一个静态站点。构建产物是一组 HTML、CSS 和少量 JavaScript，可以直接
放在静态托管上。没有数据库，没有服务端渲染，也没有在线编辑器。

内容方向只有三个：

- **LIFE**：生活记录与个人经历。
- **THOUGHTS**：想法、观察与思考。
- **CODE**：技术分享、编程实践与工程经验。

## 技术选择

| 领域 | 选择                      | 理由                                       |
| ---- | ------------------------- | ------------------------------------------ |
| 框架 | Astro                     | 默认输出静态 HTML，脚本按需加载            |
| 样式 | Tailwind CSS 4            | 设计 token 与工具类来自同一套变量          |
| 内容 | Astro Content Collections | frontmatter 有类型校验，构建期就能发现错误 |
| 高亮 | Shiki（Astro 内建）       | 构建时生成，不在客户端加载高亮库           |
| 搜索 | Pagefind                  | 对静态产物建索引，不需要搜索服务器         |

## 写作方式

一篇文章就是一个 Markdown 文件，frontmatter 描述它的元信息：

```yaml
---
title: "这个站点如何工作"
description: "一句话说明这篇文章在讲什么。"
pubDate: 2026-10-28
updatedDate: null
tags:
  - meta
category: code
draft: false
---
```

`draft` 必须显式声明。草稿不会出现在列表、归档、RSS、搜索索引或 sitemap 里，
也就不存在"忘记过滤"这类问题——过滤发生在查询层，而不是某个页面的临时判断。

## 关于对称

> 一个对称的非必要结构

排版上的约束大多来自这句话：栏宽和留白成对出现，分隔线细到几乎看不见，编号
和分类标签用同一套字距。它不服务于任何指标，只让长时间阅读舒服一点。

## 接下来

页面还很有限：只有首页、文章页和 404。归档、搜索、RSS 与部署配置会依次补上，
每个阶段结束都跑一遍完整的检查再提交。
